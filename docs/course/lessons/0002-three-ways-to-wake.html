Three ways to wake an agent

Events, schedules and heartbeats. Pick the wrong one and you either miss things or pay to wake up for nothing.

Warm-up from Lesson 1

Answer these from memory before reading on.

A. Where does an always-on agent's memory live between turns?

Saved state on the server is the only part that's always on. The VM can always be rebuilt, and the context is rebuilt on every turn.

B. What's the last stage of the wake path, before the agent goes back to sleep?

Router (dedupe, pick conversation) → queue → turn → “anything worth saying?” → send or stay quiet.

The three mechanisms

The lecture lists seven trigger sources.1 Look at how each source tells the agent to wake and they reduce to three mechanisms:

1 · Events: the default when the source can push

Ambient agents “listen to an event stream and act on it accordingly.”2 Grok Bot routines can start “from an event, such as a Slack message or a GitHub notification.”3 Two production details from Anthropic's routines docs are worth copying. First, each event gets its own session: “two PR updates produce two independent sessions.” Second, the payload arrives wrapped and labelled as untrusted data, so a leaked trigger token can't give your agent orders.4 Events also arrive in bursts. OpenClaw caps event-driven turns at one every 30 seconds per agent, with a flood guard after five starts within 60 seconds.5 That's the same problem the lecture solves by batching quick messages into one turn.

2 · Schedules: when time itself is the meaning

The lecture stores a routine as a file: prompt + weekdays 8:00. New routines need the user's OK.1 Shipping products put a floor on how often a routine can run. Grok Bot's limit is “at least five minutes apart”;3 Claude routines: “the minimum interval is one hour.” Runs don't start exactly on time either: a 9:00 run “can start several minutes late,” so the docs suggest 9:07.4 Schedules are also how you poll a source that can't push, like a web page with no API.

3 · Heartbeats: a narrow “anything need me?”

OpenClaw runs a heartbeat every 30 minutes by default: a turn in the agent's main session that replies NO_REPLY when nothing needs attention.5 Look at how OpenClaw has narrowed the heartbeat over time:

  • Heartbeats now run as a system-owned scheduled job, so there is only one scheduler.
  • Recurring checks like “inbox review, calendar sweeps” are supposed to be separate scheduled jobs. The default heartbeat “does not infer recurring work from prior chats, so a default install stays quiet instead of rehashing stale conversation context.”
  • To cut cost, isolatedSession “dramatically reduces per-heartbeat token cost” by not resending the conversation history.5

The lesson in that history

A heartbeat that is open-ended (“look around and do whatever seems useful”) is expensive and noisy, because it wakes the model to invent work. Mature systems turn each known check into an explicit schedule and keep the heartbeat for the one thing nothing else covers: noticing that something pending needs a nudge.

The decision rule

  1. Can the source push? Use an event.
  2. Is the trigger a time, or a source you have to poll? Use a schedule with an explicit saved prompt.
  3. Only an open-ended “does anything need me?” left? Use a heartbeat. Keep it narrow, isolated and quiet by default, and limit it to active hours.

One shape for every wake-up

Whatever wakes the agent, the router should receive the same record. The lecture says every wake-up records where it came from.1 In TypeScript, that's the first type you'll write for your product:

type Wake = {
  id: string;              // dedupe key: Slack event_id, `${routineId}:${scheduledFor}`, heartbeat tick time
  source: "owner" | "slack" | "github" | "webhook" | "schedule" | "heartbeat" | "background";
  conversationId: string;  // picked by the router
  trusted: boolean;        // the owner's own words vs. outside content
  payload: string;         // wrapped as untrusted data unless trusted
  receivedAt: Date;
};

Note the dedupe key for a schedule: routineId + scheduledFor. If your cron runner retries a tick, the router sees the same ID and drops it. That's the same unique-ID trick from Lesson 1, applied to time.

Feel the cost of a heartbeat

A heartbeat bills you on every tick. Play with the numbers. The price field is only an example: check your model's real price. Then try the two cheap fixes, a longer interval and fewer input tokens (an isolated, light-context session).

Now compare: if the same 1,000 users each got 5 real events a day, you would pay for 5 wake-ups per user instead of 32. Event-driven cost grows with activity, and a heartbeat's grows with the passage of time. That's the lecture's open problem made concrete: “Always-on only works if idle agents are nearly free.”6

Practice: pick the mechanism

For each feature of a product you might build, choose how the agent should wake.

1. Reply when a teammate @-mentions the bot in a Slack thread.

Slack pushes the mention. Polling would be slower and pay for empty checks.

2. Post a sales-pipeline summary every Monday at 9am.

Time itself is the meaning. Schedule it at 9:07 rather than exactly on the hour.

3. Alert the user when a competitor's pricing page changes. The site has no API and no webhooks.

The source can't push, so you poll it, and polling is a schedule with an explicit saved prompt. OpenClaw's docs put recurring checks into scheduled jobs, not the heartbeat.

4. Mid-chat, the agent starts a 40-minute research job and must follow up when it finishes.

“Background work finishing” is one of the lecture's trigger sources. The job signals completion, so don't poll for it.

5. During waking hours, nudge the user if something they promised across their open threads is going stale.

No single event and no fixed time. It's an open-ended “does anything need me?” over the main session's context. Use a heartbeat, limited to active hours and quiet by default.

6. Which mechanism costs money even on a day when nothing at all happens?

A heartbeat ticks no matter what. (A schedule does too, but it runs rarely and only for work you asked for.)
